核心（登录、组织、计费、邮件、任务）之外的一切都是可选模块：有自己的文件，通过几个列表项接入共享代码。去掉产品用不到的模块，需要理解、更新和保障安全的代码就更少。

## 模块列表

| 模块                 | 增加的功能                                                         | 依赖               |
| -------------------- | ------------------------------------------------------------------ | ------------------ |
| `account-security`   | 两步验证登录、通行密钥、已登录设备、更换邮箱、安全提醒邮件         |                    |
| `admin`              | 位于 `/admin` 的运营人员后台：搜索、封禁、以用户身份登录、操作日志 |                    |
| `enterprise-sign-in` | 全站可用的 Microsoft、Apple 以及任意 OpenID Connect 提供商         |                    |
| `paddle`             | Paddle 计费（`BILLING_PROVIDER=paddle`）                           |                    |
| `trials-seats`       | 试用提醒邮件；随成员数变化的按成员计费订阅                         |                    |
| `uploads`            | 头像、Logo 和附件，存储在 S3 或本地                                |                    |
| `activity`           | 设置 > 活动记录                                                    |                    |
| `api`                | API 密钥和 `/api/v1`                                               | `usage`            |
| `webhooks`           | 设置 > Webhooks                                                    |                    |
| `usage`              | 按量计费的 API 请求、额度包、超额计费                              |                    |
| `sso`                | 按组织的 SAML、SCIM、强制两步验证或 SSO                            | `account-security` |

## 在 setup 时选择

在全新的副本上，`pnpm dev:setup` 会列出一份默认全部勾选的模块清单。取消勾选项目用不到的模块，它们会在你开始构建之前被移除。它只在第一次（`.env` 还不存在时）并且只在交互式终端中询问，所以 CI 会保留全部模块。

## 之后再移除

```bash
pnpm module:remove webhooks
```

不带名称时会显示清单；`--list` 列出仍保留的模块，`--yes` 跳过确认。依赖被移除模块的其他模块也会一并移除，命令会在询问前说明：移除 `usage` 也会移除 `api`。

它要求 git 工作区是干净的（先提交，或者加 `--force`），这样移除就是一次可以用 `git diff` 审查的改动。它会删除模块的文件和 npm 包，并移除指向它们的内容：import、列表项、数据表、消息区域和消息键。如果发现无法安全移除的用法（例如你自己的代码调用了该模块），它会在改动任何内容之前停下，并指出文件和行号。然后运行：

```bash
pnpm check
```

<Note>

模块的数据库表会保留；空表不会有任何影响。要删除它们，运行 `pnpm auth:generate` 和 `pnpm db:generate`，并在执行迁移之前先读一遍：它会删除这些表及其中的数据。

</Note>

## 恢复模块

撤销移除它的那次提交即可，在它之上构建的东西还不多时这样最干净。之后再想恢复，就从你的 Kitewell Pro 副本中把它的文件复制回来。合并新版本的 Kitewell Pro 之后，对合并带回来的模块再运行一次 `pnpm module:remove`。
